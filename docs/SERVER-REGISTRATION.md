# التسجيل والحفظ الخادمي — بيئة تطوير

الحالة: نُفذت أول وحدة من [خطة MVP](REAL-MVP-PLAN.md): حسابات وجلسات ورفع وثائق وطلبات مراجعة في **بيئة محلية للاختبار**. لا يثبت ذلك جاهزية الإنتاج أو نجاح التحقق الميداني. لم تُشتر خدمة أو تُنشأ قاعدة إنتاجية.

## ما يعمل

- Fastify وTypeScript، وملف migration لإنشاء الحسابات والأدوار وتحديات الرمز والجلسات والوثائق ومراجعات السائق وسجل التدقيق.
- PostgreSQL مضمّن عبر PGlite يحفظ على القرص تحت `.local-auth/database/`، وليس `localStorage`. خيار اتصال PostgreSQL خارجي عبر `DATABASE_URL` موجود لكنه لم يُختبر على خادم خارجي في هذا التسليم.
- تسجيل الراكب/السائق وتوحيد رقم العراق بما في ذلك الأرقام العربية؛ تحديات ستة أرقام تنتهي خلال خمس دقائق وتستهلك مرة واحدة، بحد خمس محاولات وفاصل إرسال دقيقة وعشرة طلبات يومية لكل رقم. يوجد أيضًا حد طلبات حسب IP؛ لا يُوثق proxy headers تلقائيًا.
- رمز عشوائي للجلسة يُحفظ ملخصه في قاعدة البيانات، وcookie بـHttpOnly وSameSite=Strict لمدة سبعة أيام. Secure عند أصل HTTPS، وغير مفعلة محليًا على HTTP فقط. التعديلات تتطلب Origin مطابقًا ورمز CSRF. لا تحفظ رموز الدخول أو بيانات العميل في `localStorage` في وضع الخادم.
- تعديل الاسم، وبقاء الحساب بعد إعادة فتح الصفحة أو الخادم أو إعادة تسجيل الدخول من جهاز آخر؛ الخروج يبطل الجلسة ولا يحذف الحساب.
- رفع صورة فعلية والتحقق من فكّها عبر Sharp، وقبول PNG/JPEG/WebP حتى 5 ميغابايت و16 مليون بكسل، وإعادة ترميزها JPEG مع إزالة metadata غير المطلوبة. الملف محفوظ فعليًا خارج `www/` بصلاحيات خاصة. هذا ليس خدمة فحص فيروسات أو مخزن S3 إنتاجيًا.
- طلب السائق يبقى `pending_review`. لا يوجد زر قبول ذاتي في وضع الخادم؛ المراجعة بأداة مشغّل محلي منفصلة ومفتاح لا يصل إلى المتصفح. القرار يسجل في audit، ولا يمنح شارة الثقة تلقائيًا. إعادة تقديم بيانات السائق تعيد الطلب إلى المراجعة.
- رفض الوصول لوثيقة حساب آخر، وتجاهل صلاحيات مزورة من العميل عبر رفض حقول إضافية مثل `verified` و`role:reviewer`.

## التشغيل

المتطلبات: Node.js 22+ وnpm؛ التحقق الحالي على Node 24 وChromium. من جذر المستودع:

```bash
npm ci
npm run dev:server
```

الخادم يستمع إلى `127.0.0.1` على المنفذ `4180` فقط. افتح مسار `/register.html` على هذا الخادم في متصفحك المحلي. يمكن تغيير `PORT` إلى منفذ تطوير آخر؛ يجب استخدام عنوان `127.0.0.1` نفسه لأن فحص Origin صارم. GitHub Pages لا يشغل هذا الخادم.

الحسابات في شاشة «التسجيل / حسابي». خطوات الاستخدام:

1. اختر الدور، وأدخل بيانات اصطناعية ورقمًا عراقيًا للاختبار، ووافق على حفظ بيانات الاختبار.
2. بعد طلب الرمز يظهر **معرف طلب** لا رمز SMS. شغّل في Terminal آخر:

   ```bash
   npm run auth:operator -- code <challenge-id>
   ```

3. أدخل رمز الاختبار الناتج في شاشة التحقق. لم تُرسل رسالة للهاتف، وامتلاك الرمز المحلي لا يثبت ملكية الرقم.
4. بعد الدخول يظهر الحساب المحفوظ على الخادم ويمكن تعديل الاسم أو تسجيل الخروج. إعادة الدخول بالهاتف نفسه تعيد الحساب نفسه بعد تحدٍ جديد؛ انتظر مهلة الدقيقة قبل إعادة طلب الرمز.
5. للسائق، ارفع صورة اصطناعية وأرسل بيانات المركبة. للمراجع المحلي:

   ```bash
   npm run auth:operator -- pending
   npm run auth:operator -- document <driver-user-id>
   npm run auth:operator -- review <driver-user-id> approved "فحص بيانات الاختبار"
   # أو rejected مع سبب مناسب
   ```

   الأمر `document` يحفظ نسخة مراجعة خاصة تحت `.local-auth/review-<id>.jpg` ليطالعها المشغّل. لا تقبل طلبًا دون فحصه. حدّث شاشة الحساب لمشاهدة القرار؛ لا ادعاء بإرسال إشعار.

مفاتيح auth والمراجع تتولد محليًا وتُحفظ بصلاحية 0600 داخل مجلد 0700. لا تعرضها ولا تضعها في Git. صندوق رموز الاختبار يحتوي رموزًا صريحة للاختبار فقط في `.local-auth/test-inbox/` ولا يخدمه HTTP؛ يحتاج حذفًا دوريًا يدويًا في التطوير. لا توجد مسارات HTTP عامة لقراءة الأكواد.

يمكن تخصيص مجلد البيانات عبر `KHATTI_DATA_DIR`. لا تحذفه أو تشغل اختبارات مدمرة عليه إن كنت تريد الاحتفاظ بحسابات التطوير. الاختبارات تستخدم مجلدات مؤقتة منفصلة وصورًا اصطناعية وتحذفها بعد الإنهاء. تحتاج نسخة ملفات PGlite إلى إيقاف الخادم أولًا؛ إجراءات النسخ والاستعادة الإنتاجية لم تنفذ بعد.

## فصل الخادم عن المحاكاة

على استضافة ثابتة، `assets/runtime.js` يختار وضع العرض التجريبي السابق. خادم التطوير يخدم نسخة runtime تختار وضع الحسابات الخادمية. شاشة التسجيل تكتشف الوضع وتستخدم API من الأصل نفسه؛ لا عنوان API قابلًا للتحويل إلى جهة أخرى من query string.

في وضع الخادم لا تُنشأ بذور المحاكاة ولا تُقرأ حسابات `khatti_demo_v1_*` كجلسات خادمية. صفحات الراكب والسائق والأهل غير المرتبطة تعرض أنها غير متاحة بهذا الوضع وتعيد المستخدم إلى حسابه. الحجز والتتبع والدفع والتقييم **لم تتحول إلى خدمات حقيقية** بعد، فلا يتم تمرير الحساب المحفوظ إلى تدفقات حجز وهمية. الواجهات والألوان وCSS العربية محفوظة.

Capacitor ما زال يغلف العرض الثابت؛ ربط الموبايل بالخادم يحتاج أصل HTTPS موثوقًا وتصميم الجلسات والتجديد والتخزين الآمن واختبارات الجهاز. لم يضف هذا التغيير تخزين Keychain/Keystore أو تطبيقًا منشورًا أو APK/IPA جديدًا.

## API المنفذ

| المسار | الشرط |
|---|---|
| `GET /v1/health` | صحة قاعدة البيانات وحالة SMS؛ يعيد `productionReady:false` |
| `POST /v1/auth/otp/request` | name، phone، role، consent=true؛ يعيد challengeId دون code |
| `POST /v1/auth/otp/verify` | challengeId وcode؛ يصدر cookie ويعيد user وcsrfToken |
| `GET /v1/me` | cookie صالحة؛ يقرأ حساب الجلسة فقط |
| `PATCH /v1/me` | cookie وCSRF وOrigin؛ تعديل name فقط |
| `POST /v1/auth/logout` | cookie وCSRF وOrigin؛ يبطل الجلسة دون حذف الحساب |
| `POST /v1/driver/document-uploads` | دور driver وCSRF وOrigin؛ صورة base64 سليمة |
| `GET /v1/driver/documents/:id` | صاحب الوثيقة فقط؛ no-store وattachment |
| `POST /v1/driver/submissions` | وثيقة مملوكة للسائق وبيانات مركبة صالحة |
| `GET /v1/internal/driver-reviews` | مفتاح المشغّل المحلي؛ أول 100 طلب معلق |
| `GET /v1/internal/driver-reviews/:id/document` | مفتاح المشغّل؛ الوثيقة محل المراجعة |
| `POST /v1/internal/driver-reviews/:id/decision` | مفتاح المشغّل وOrigin؛ approved/rejected مع reason |

السجلات معطلة افتراضيًا لتجنب تسريب الهواتف والأكواد. الأخطاء منظمة ولا تكشف stack traces. الوصول للملفات المخفية أو مفاتيح التشغيل عبر خادم الويب محظور، ومجلد الخادم وقاعدة البيانات لا يدخل حزمة `www/`.

## الاختبارات وحدود التسليم

```bash
npm run typecheck
npm run test:server
npm run test:server-browser
npm test
```

اختبارات API تشغل PGlite حقيقيًا وتتحقق من صلاحيات الوثائق وCSRF وOTP وفشل الإرسال وإبطال الجلسات وبقاء البيانات بعد إغلاق القاعدة وفتحها. اختبارات Chromium تنفذ التسجيل ورفع الصورة من الواجهات والتحقق من بقاء البيانات بعد reload ومسح localStorage وفتح تبويب آخر. تُختبر الواجهات التجريبية السابقة أيضًا لمنع كسرها.

النواقص قبل تشغيل عملاء حقيقيين:

- اختيار مزود SMS يدعم العراق واختبار التسليم وإدارة الأسرار وحد الإنفاق. واجهة `SmsSender` منفصلة لتوصيله؛ **لا موصل مزود حي مفعّل حاليًا**.
- الاستضافة وHTTPS وقاعدة PostgreSQL خارجية وتخزين خاص مُدار وفحص ملفات وتشغيل النسخ الاحتياطية والاستعادة. مسار pg مكتوب ولم يُختبر مع PostgreSQL خارجي.
- سياسة خصوصية إنتاجية وفترات الاحتفاظ والحذف واسترداد الحساب عند فقد الهاتف، ومصادقة قوية للمراجعين وهويات فردية بدل مفتاح المشغّل المحلي.
- اختبارات تزامن وضغط ونشر واستعادة واعتمادات production، ثم تنفيذ بقية وحدات MVP في الخطة وربط الموبايل.

التشغيل مع `NODE_ENV=production` مرفوض صراحة، ولا يمكن تبديل `SMS_MODE` إلى live دون تنفيذ موصل فعلي. لا يمكن الاعتماد على هذا الخادم للتحقق من هوية مدنية أو ملكية هاتف أو قبول وثائق حقيقية. طلب المستخدم بتنفيذ وحدة التسجيل لا يثبت تحقق الهدف الميداني ولا يجيز إعلان المنتج جاهزًا للإطلاق.

## دليل التحقق لهذا التسليم

في 14 تشرين الأول 2026، نجح تثبيت نظيف عبر `npm ci` وفحص TypeScript، ثم نجحت جميع اختبارات `npm test`: 6 اختبارات منطق وحزمة، و15 سيناريو API ضمن مجموعة Node واحدة (يعرض مشغّل Node العدد 16 بإضافة المجموعة)، و12 اختبار متصفح للعرض السابق، واختبارا متصفح للحسابات الخادمية. لا فشل أو تخطٍ في الجولة النهائية. من بينها تحقق متزامن للرمز: جلسة واحدة ناجحة فقط، واختبار انتهاء الجلسة وإعادة فتح قاعدة البيانات.

نجح تشغيل `npm run dev:server` وفحص الصحة الذي أعاد `status:ok` و`smsMode:test` و`productionReady:false`، ونجحت قراءة قائمة المراجعة عبر أداة المشغّل. `npm audit` أعاد صفر ثغرات وقت الفحص؛ ليس ذلك بديلًا عن مراجعة أمنية إنتاجية. جرى التأكد من تجاهل مجلد بيانات التشغيل والمفاتيح في Git ومن عدم تغيير `assets/style.css` أو `PROMPT.md`.
